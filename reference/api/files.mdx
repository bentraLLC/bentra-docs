---
title: "Files and versions"
---

Workflows stored in Bentra (`source.type` `local`) keep their files in a **draft** you edit, and immutable **versions** cut from it. Only the active version runs; editing the draft changes nothing until you publish. Repo-backed workflows have no draft: the file endpoints and `POST versions/` return `404` for them, but they have versions too, published from the repository by a sync (`GET`/`POST workflows/{id}/sync/` in [Workflows](/reference/api/workflows)). `GET versions/` lists them with their `commit_sha`, and `activate` rolls back to one, which also turns automatic sync off until the newest version is activated again.

| Method | Path | Scope | MCP tool |
|---|---|---|---|
| `GET` | `workflows/{id}/files/` | `read:workflows` | `list_files` |
| `POST` | `workflows/{id}/files/` | `edit:workflows` | `create_file` |
| `GET` | `workflows/{id}/files/content/?path=` | `read:workflows` | `read_file` |
| `PUT` | `workflows/{id}/files/content/` | `edit:workflows` | `update_file` |
| `DELETE` | `workflows/{id}/files/content/?path=` | `edit:workflows` | `delete_file` |
| `GET` | `workflows/{id}/versions/` | `read:workflows` | `list_versions` |
| `POST` | `workflows/{id}/versions/` | `edit:workflows` | `publish_version` |
| `POST` | `workflows/{id}/versions/{version_id}/activate/` | `edit:workflows` | `activate_version` |

Reads need `workflow.view`; writes need `workflow.edit`.

## Files

Every workflow has `workflow.yml` (the steps); request workflows also have `form.yml` ([form syntax](/reference/form-syntax)). Both are at the top level, are required and can't be deleted. Python dependencies go in `requirements.txt`, and a `README.md` is optional.

### `GET workflows/{id}/files/`

```json
{"success": true, "read_only": false,
 "files": [{"path": "workflow.yml", "is_required": true},
           {"path": "requirements.txt", "is_required": false}]}
```

`?version=<version_id>` lists a version's files instead (`read_only: true`).

### `GET workflows/{id}/files/content/?path=workflow.yml`

```json
{"success": true, "path": "workflow.yml", "content": "name: …", "read_only": false}
```

Also takes `?version=`.

### `POST workflows/{id}/files/`

`{"path": "scripts/create.sh", "content": "#!/bin/bash\n…"}` creates a draft file. Paths are relative, without `..`. `409` if the path exists; `400` for an invalid path, too many files, or too much content.

### `PUT workflows/{id}/files/content/`

`{"path": "…", "content": "…"}` replaces an existing draft file's content.

### `DELETE workflows/{id}/files/content/?path=…`

Deletes a draft file. Required files return `400`.

## Validate

### `POST workflows/{id}/files/validate/`

Checks a `workflow.yml` without saving anything. Send `{"content": "…"}` to check that text, or an empty body to check what is stored: the draft, or a repo-backed workflow's active version. Works for every workflow; needs `read:workflows`.

```json
{
  "success": true,
  "valid": false,
  "errors": [
    {"message": "Step 2: Unknown key 'runs'. Did you mean 'run'?", "line": 7}
  ],
  "warnings": [],
  "steps": [
    {"number": 1, "name": "Plan", "id": "plan", "kind": "run", "kind_label": "Script", "if": "", "continue_on_error": false, "line": 3},
    {"number": 2, "name": "Apply", "id": "", "kind": "", "kind_label": "", "if": "steps.plan.outcome == 'success'", "continue_on_error": false, "line": 6}
  ]
}
```

See [What Bentra checks](/reference/workflow-syntax#what-bentra-checks).

### `GET schemas/workflow/`

The JSON Schema (draft 2020-12) for `workflow.yml`: the allowed keys and their types. Conditions, step ids and module steps are checked by the validate endpoint, not by the schema.

## Versions

### `GET workflows/{id}/versions/`

```json
{"success": true, "versions": [
  {"id": "…", "version_number": 2, "label": "add region", "created_at": "…", "created_by": "alice", "is_active": true, "commit_sha": ""},
  {"id": "…", "version_number": 1, "label": "", "created_at": "…", "created_by": "alice", "is_active": false, "commit_sha": ""}
]}
```

### `POST workflows/{id}/versions/`

`{"label": "add region"}`. Snapshots the draft as the next version and makes it active. `400` when `workflow.yml` has problems or a request workflow's form doesn't validate: `error` is the first problem and `issues` lists them all.

```json
{"success": false, "error": "workflow.yml is invalid (line 7): Step 2: Unknown key 'runs'. Did you mean 'run'? (and 1 more)",
 "issues": [{"file": "workflow.yml", "message": "Step 2: Unknown key 'runs'. Did you mean 'run'?", "line": 7},
            {"file": "workflow.yml", "message": "Step 2: A step needs one of run, module or github_workflow_dispatch.", "line": 6}]}
```

### `POST workflows/{id}/versions/{version_id}/activate/`

Makes an existing version the one that runs: pin a known-good version or roll back. The draft isn't changed. Returns `{"success": true, "version": {…}}`, or `400` with `issues` when that version's files don't pass today's checks.
