---
title: "Variables"
---

Variables reach a workflow's steps as environment variables. They come from **variable collections** (reusable sets managed by their maintainers, usable in the workspaces they're shared with, and attachable to any number of workflows) and from the workflow's **own variables**, which override collection values. Among attached collections, a later one overrides an earlier one.

Secret values are encrypted with a key unique to your organization and are **never returned**: responses show a masked `display_value`.

| `POST` | `variable-collections/` | `edit:variables` | `create_variable_collection` |
| `PATCH` | `variable-collections/{id}/` | `edit:variables` | `update_variable_collection` |
| `DELETE` | `variable-collections/{id}/` | `edit:variables` | `delete_variable_collection` |
| `PATCH` | `variable-collections/{id}/sharing/` | `edit:variables` | `set_collection_sharing` |

| `DELETE` | `variable-collections/{id}/variables/{variable_id}/` | `edit:variables` | `delete_collection_variable` |
| `GET` | `workflows/{id}/variables/` | `read:variables` | `list_workflow_variables` |
| `POST` | `workflows/{id}/variables/` | `edit:variables` | `add_workflow_variable` |

| `DELETE` | `workflows/{id}/variables/{variable_id}/` | `edit:variables` | `delete_workflow_variable` |

| `DELETE` | `workflows/{id}/variable-collections/{collection_id}/` | `edit:variables` | `detach_collection` |

**Permissions:** reading collections needs `org.view_variable_collections`. Owners and admins (`org.manage_variable_collections`) can create and change any collection. Members (`org.create_variable_collections`) can create collections available in a workspace they belong to, except the default workspace, and change the collections they maintain, directly or through a group. A workflow's variables and attached collections need `workflow.manage_variables`.

## A variable

```json
{"id": "…", "key": "AWS_REGION", "display_value": "eu-west-1", "is_secret": false, "treat_as_json": false}
```

Body for creating or changing one:

| Field | Notes |
|---|---|
| `key` | Letters, digits and underscores, not starting with a digit. Unique within the collection or workflow. Required on create. |
| `value` | The value. For a secret, write-only. |
| `is_secret` | Store the value encrypted; it's never returned. |
| `treat_as_json` | Validate the value as JSON. |

`PATCH` changes only what you send. Changing a key or value of a secret never reveals the old value.

<Note>
**Secrets and agents**

An agent can set a secret if you give it the value, but the value then passes through the conversation. Prefer entering secret values in Bentra.
</Note>

## Collections

### `GET variable-collections/`

Owners and admins see every collection. Everyone else sees the ones they maintain and the ones usable in a workspace they belong to (shared with it, or with every workspace). `?workspace=<slug>` narrows the list to the collections that workspace's workflows can attach. Paginated.

```json
{"count": 1, "next": null, "previous": null,
 "results": [{"id": "…", "name": "AWS prod", "description": "",
              "visibility": "selected_workspaces", "shared_with": ["platform", "data"],
              "maintainers": [{"id": "…", "type": "user", "email": "dana@acme.com"}],
              "created_by": "dana@acme.com", "created_at": "…", "updated_at": "…"}]}
```

`maintainers` (users and groups) manage the collection. `visibility` is `selected_workspaces` (the ones in `shared_with` can attach it) or `all_workspaces`. Those workspaces can attach it but not change it.

### `GET variable-collections/{id}/`

The collection plus `variables`.

### `POST variable-collections/`

`{"name": "AWS prod", "description": "…", "workspaces": ["platform"]}` → `201`. `workspaces` are the ones that can attach it; members need at least one, and only non-default workspaces they belong to. Owners and admins can send `"visibility": "all_workspaces"` instead. You become its maintainer. `403` if you can't create collections there. `502` if secret storage is unavailable.

### `PATCH variable-collections/{id}/`

`{"name": "…", "description": "…"}`.

### `DELETE variable-collections/{id}/`

Deletes the collection, its variables and their secrets, and detaches it from workflows. Returns `204`.

### `PATCH variable-collections/{id}/sharing/`

`{"visibility": "selected_workspaces", "workspaces": ["data", "ml"]}`, every field optional.

- `workspaces` replaces the list of workspaces that can attach it. Members can add only non-default workspaces they belong to; workspaces they can't add stay on the list when they save.
- `visibility` (`selected_workspaces` or `all_workspaces`) is owners and admins only.
- Returns `409` with `blocking_workflows` (`slug`, `name`, `workspace`) when a workflow in a workspace that would lose access still has the collection attached. Nothing changes.

### `POST variable-collections/{id}/maintainers/`

`{"user": "ana@acme.com"}` or `{"group": "<group id>"}` → `201` with the maintainer. Needs `edit:variables`.

### `DELETE variable-collections/{id}/maintainers/{maintainer_id}/`

Returns `204`. Only owners and admins can remove the last maintainer.

## A workflow's variables

### `GET workflows/{id}/variables/`

```json
{"success": true,
 "variables": [{"id": "…", "key": "BUCKET_PREFIX", "display_value": "acme-", "is_secret": false, "treat_as_json": false}],
 "collections": [{"id": "…", "name": "AWS dev", "order": 1}, {"id": "…", "name": "AWS prod", "order": 2}],
 "overrides": [{"key": "AWS_SECRET_ACCESS_KEY",
                "used": {"type": "collection", "id": "…", "name": "AWS prod"},
                "overridden": [{"type": "collection", "id": "…", "name": "AWS dev"}]}]}
```

`collections` is in precedence order: later ones override earlier ones, and the workflow's own variables override them all.

`overrides` lists every key defined in more than one place, sorted by key: `used` is the definition a run gets, `overridden` the ones it ignores (nearest first). `type` is `collection` or `workflow`. Only keys are compared; no values are read. A run decrypts only the `used` definitions, so a broken overridden secret never fails it.

### `POST workflows/{id}/variable-collections/`

`{"collection_id": "…"}` attaches a collection usable in the workflow's workspace (its own, one shared with it, or one shared with every workspace), after the existing ones. `404` if it isn't usable there; `409` if already attached.

### `DELETE workflows/{id}/variable-collections/{collection_id}/`

Detaches it.
