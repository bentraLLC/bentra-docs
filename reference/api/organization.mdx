## `GET connectors/`

VCS connectors you can see. Owners and admins see every connector. Everyone else sees the ones they maintain and the ones usable in a workspace they belong to (shared with it, or with every workspace). `?workspace=<slug>` narrows the list to the connectors a workflow in that workspace can use. Paginated.

```json
{"count": 1, "next": null, "previous": null,
 "results": [{"id": "6c2f…", "name": "GitHub", "description": "", "vcs_type": "github",
              "auth_type": "github_app", "owner": "acme",
              "visibility": "selected_workspaces", "shared_with": ["platform", "data"],
              "maintainers": [{"id": "…", "type": "user", "email": "dana@acme.com"},
                              {"id": "…", "type": "group", "group_id": "…", "name": "Platform"}],
              "created_by": "dana@acme.com"}]}
```

`maintainers` manage the connector (owners and admins manage every connector). `visibility` is `selected_workspaces` (the ones in `shared_with` can use it) or `all_workspaces`. `owner` is the GitHub organization.

Connectors hold credentials, so you add them and change their credentials in **Settings → Connectors**, not through the API.

## `PATCH connectors/{id}/`

Rename a connector or change which workspaces can use it. Allowed for owners and admins, and for its maintainers. Every field is optional.

```json
{"name": "Platform GitHub", "visibility": "selected_workspaces", "workspaces": ["data", "ml"]}
```

- `workspaces` replaces the list of workspaces that can use it. Members can add only non-default workspaces they belong to; workspaces they can't add stay on the list when they save.
- `visibility` (`selected_workspaces` or `all_workspaces`) is owners and admins only. The workspace list is kept while it's `all_workspaces`.
- `409` with `blocking_workflows` (`slug`, `name`, `workspace`) when a workflow that uses the connector would lose it. Nothing changes; switch those workflows to another connector first.

## `POST connectors/{id}/maintainers/`

Add a maintainer: `{"user": "ana@acme.com"}` (an organization member) or `{"group": "<group id>"}`. Returns `201` with the maintainer (`id`, `type`, …). Needs `manage:connectors` and the right to manage the connector.

## `DELETE connectors/{id}/maintainers/{maintainer_id}/`

Remove a user or group. Returns `204`. Only owners and admins can remove the last maintainer.

## `POST connectors/{id}/test/`

Checks the stored credentials still work by listing one repository. Returns `{"success": true}`, or `502` with the provider's error.

## `GET connectors/{id}/repositories/`

Repositories the connector can reach.

| Query | Default | Notes |
|---|---|---|
| `q` | | Filter by name. |
| `page` | 1 | |
| `per_page` | 20 | Max 50. |

```json
{
  "success": true,
  "repos": [{"name": "infra", "full_name": "acme/infra", "html_url": "https://github.com/acme/infra",
             "pushed_at": "2026-10-08T21:14:03Z", "private": true}],
  "page": 1, "per_page": 20, "has_next": false, "has_prev": false, "total_count": 1
}
```

`502` if the provider refuses (for example, the connector's token expired).

## `GET connectors/{id}/refs/`

A repository's default branch, branches and tags (first 100 of each), to pick what a workflow tracks or pins.

`GET connectors/6c2f…/refs/?repo=acme/infra`

```json
{"success": true, "repo": "acme/infra", "default_branch": "main",
 "branches": ["main", "release"], "tags": ["v1.2.0", "v1.1.0"]}
```

`400` if `repo` isn't `owner/repo`; `502` if the repository doesn't exist or the connector can't reach it.

## `GET runner-pools/`

Pools a workflow can be pinned to with [`PATCH workflows/{id}/`](/reference/api/workflows#patch-workflowsid). Pools hold runner tokens, so they're created and changed in **Settings → Runner Pools**.

```json
{"count": 1, "next": null, "previous": null,
 "results": [{"id": "…", "name": "Default", "slug": "default", "description": "",
              "scope_type": "organization", "workspace": null, "backend_type": "kubernetes",
              "is_default": true}]}
```

## Request portal branding

The request portal (`/orgs/<org>/portal/`) shows the portal name, welcome message, accent colour and logo.

**Permission to change:** `org.manage_settings`. Requesters (portal-only members) can't use these endpoints.

### `GET branding/`

```json
{"portal_name": "Acme Help", "welcome_message": "Ask for infrastructure here.",
 "accent_color": "#1f6feb", "logo_url": "/branding/acme/logo?v=3"}
```

### `PATCH branding/`

Any of `portal_name` (up to 100 characters), `welcome_message` (up to 1000), `accent_color` (hex, e.g. `#1f6feb`). An empty string clears a field.

### `PUT branding/logo/`

Multipart upload with a `logo` file: PNG, JPEG or WebP, up to 256 KB. SVG isn't accepted.

```bash
curl -X PUT -H "Authorization: Bearer $BENTRA_TOKEN" \
  -F logo=@logo.png https://bentra.example.com/orgs/k3j9x2m4pqrt/api/v1/branding/logo/
```

### `DELETE branding/logo/`

Removes the logo. Returns `204`.
